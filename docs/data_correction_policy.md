# Data Correction Policy

A correction is a verified error in source acquisition, transformation, disclosure, metadata, or presentation. Reports are triaged by scientific, privacy, legal, and operational severity. A correction requires reproduced evidence, method-owner review, regression testing, a new immutable release ID, a `supersedes` link, changelog entry, and retention of the prior release. Silent byte replacement is prohibited. Emergency takedown is limited to legal, security, privacy, or critical source-rights risk.
